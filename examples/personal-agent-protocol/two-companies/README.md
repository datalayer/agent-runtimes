# PAP Two Companies

Two companies working together, in PAP draft 0.3's own terms. Draft 0.3
defines no company-to-company protocol, so this is **composition**:

- To Ada's personal agent, Atlas, **Ledgerly** (an accounting firm) is a PAP
  company: discovery, Sessions, sign-in, a company agent, and Operations.
- To **Northwind Bank**, Ledgerly is a PAP personal agent acting for the same
  Ada, with its own `client_id` and keys, connected to her Northwind account
  through Device Sign-In that she approves on Northwind's page.

Every approval is an Operation, never a chat message:

1. Northwind's payment proposal reaches Ada as a Ledgerly operation quoting
   Northwind's summary. She approves it in Atlas; Ledgerly confirms that exact
   revision at Northwind with `approved_by: user`.
2. A bounded standing permission is itself an operation Ada approves.
3. Within its bounds, Ledgerly confirms Northwind's next proposal with
   `approved_by: standing_permission` and tells Ada what was done; beyond
   them, Ada is asked again.

The tool returns the summaries, results, and who approved each payment at
Northwind. User codes, tokens, assertions, and proofs stay with the hosts.

```bash
loop apps run examples/personal-agent-protocol/two-companies/app.py
```

The **PAP Two Companies** UI example replays the same world step by step,
from a trace generated by [`../traces/generate.py`](../traces/generate.py).

and the [extensions guide](https://personal-agent-protocol.datalayer.tech/guides/extensions/).
