# Subagents

Agent Runtimes supports multi-agent delegation via the in-repo subagents capability (`agent_runtimes/subagents/`). An orchestrator agent can delegate tasks to specialised subagents, each running independently with its own model and instructions.

## How It Works

1. **Agent spec** declares a `subagents` block listing the available subagents
2. **Code generation** (`make specs`) compiles the YAML into Python/TypeScript catalogs
3. **Agent creation** reads the spec and builds a `SubagentsCapability` via `factory.py`
4. **Runtime** — the orchestrator agent receives a `delegate_task` tool and a dynamic system prompt listing the subagents

### Architecture

```
┌─────────────────────────────────────────────────────┐
│                 Orchestrator Agent                   │
│  (receives task, check_task, list_active_tasks, …)  │
│                                                     │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐ │
│  │  Researcher  │  │   Writer    │  │  General    │ │
│  │  subagent    │  │  subagent   │  │  Purpose    │ │
│  └─────────────┘  └─────────────┘  └─────────────┘ │
└─────────────────────────────────────────────────────┘
```

## Agent Spec Configuration

Add a `subagents` block to any agent YAML spec:

```yaml
subagents:
  default_model: "bedrock:us.anthropic.claude-sonnet-4-5-20250929-v1:0"
  include_general_purpose: true
  max_nesting_depth: 0
  subagents:
    - name: researcher
      description: "Researches topics and provides analysis"
      instructions: >
        You are a thorough research assistant...
      preferred_mode: sync
      typical_complexity: moderate
      can_ask_questions: true
      max_questions: 3

    - name: writer
      description: "Writes clear, structured content"
      instructions: >
        You are a skilled technical writer...
      preferred_mode: sync
      typical_complexity: moderate
      can_ask_questions: false
```

See the [agentspecs subagents documentation](https://agentspecs.datalayer.tech/subagents) for the full YAML schema reference.

## Runtime Integration

### Capability Factory

When an agent is created from a spec containing `subagents`, the capability factory in `agent_runtimes/capabilities/factory.py` automatically:

1. Converts each `SubAgentspecConfig` into a `SubagentDefinition`
2. Creates a `SubagentsCapability` with the resolved default model
3. Adds it to the agent's capability list

```python
from agent_runtimes.subagents import SubagentDefinition, SubagentsCapability

capability = SubagentsCapability(
    subagents=[
        SubagentDefinition(
            name="researcher",
            description="Researches topics...",
            instructions="You are a thorough research assistant...",
        ),
    ],
    default_model="bedrock:us.anthropic.claude-sonnet-4-5-20250929-v1:0",
    include_general_purpose=True,
)
```

### Delegation Tool

The orchestrator agent receives a single delegation tool at runtime:

| Tool | Description |
|------|-------------|
| `delegate_task` | Run a named subagent on a self-contained task and return its final answer |

Each delegation runs the subagent in an isolated child run. Token and request
usage are forwarded to the parent run so budget limits stay accurate.

### Dynamic System Prompt

The `SubagentsCapability` contributes a system prompt section listing the
available subagents with their names and descriptions, so the model knows what
it can delegate to.

## Subagents Over A2A

A subagent need not run inside the orchestrator's process. Give it an `a2a`
block and it becomes a *separate agent* reached over the
[A2A protocol](https://a2a-protocol.org): the same `delegate_task` tool, the
same events on the orchestrator's stream, but the run happens in another
agent — launched from its own agentspec, with its own tools and guardrails.

```yaml
subagents:
  include_general_purpose: false
  subagents:
    - name: researcher
      description: "A separate research agent, reached over A2A"
      ref: example-a2a-researcher:0.0.1
      a2a:
        launch: auto      # local | cloud | auto (default)
    - name: reviewer
      description: "An agent already running elsewhere"
      a2a:
        url: https://agents.example.com/api/v1/a2a/agents/reviewer
```

Either `url` names an agent already answering, or `ref` names the agentspec
to launch one from. With `launch: auto` the agent is launched where the
orchestrator runs: beside it on the local `agent-runtimes` server, or on a
Datalayer runtime when the orchestrator is itself a cloud runtime. Launching
goes through the client the CLI and the evals already use
(`ensure_local_agent`, `AgentClient.create_runtime`), so there is one way of
starting agents. The launched agent is registered with the `a2a` transport and
kept for the next delegations; every delegation to it from one orchestrator
shares one A2A context, so it keeps the thread.

Serving side, every agent registered with the `a2a` transport is mounted at
`/api/v1/a2a/agents/{agent_id}` by a FastA2A application whose worker runs the
agent *adapter* — MCP servers, skills, codemode, guardrails and approvals apply
as over the other transports — and streams the run over `message/stream`:
each text delta as an artifact chunk, each tool call and result as a `working`
status carrying a data part, the whole answer as the last chunk, then the
final status.

On the orchestrator's stream the `agent.subagent` events carry
`transport: "a2a"`, the agent's `url`, where it was launched, its card, its
task id and the task's states (`status` phase), so a UI can tell a remote run
from an in-process one. The `AgentA2AExample` shows it with the A2A sidebar
plugin (`@datalayer/loop-plugin-a2a-sidebar`): the remote agents, their status
and card, and the live run box.

## TypeScript Types

The TypeScript types for subagents are available in the `@datalayer/agent-runtimes` package:

```typescript
import type { SubAgentspecConfig, SubAgentsConfig } from '@datalayer/agent-runtimes';

const config: SubAgentsConfig = {
  subagents: [
    {
      name: 'researcher',
      description: 'Researches topics...',
      instructions: 'You are a thorough research assistant...',
      preferredMode: 'sync',
      typicalComplexity: 'moderate',
      canAskQuestions: true,
      maxQuestions: 3,
    },
  ],
  defaultModel: 'bedrock:us.anthropic.claude-sonnet-4-5-20250929-v1:0',
  includeGeneralPurpose: true,
  maxNestingDepth: 0,
};
```

## Example

The `AgentSubagentsExample` demonstrates the full workflow:

```bash
EXAMPLE=AgentSubagentsExample npm run dev
```

This creates an orchestrator agent from the `example-subagents` spec with a researcher
and writer subagent. The sidebar shows available subagents and delegation tools.

The built-in `example-subagents` spec is available in `agentspecs/agentspecs/agents/example-subagents.yaml` and demonstrates:
