# Agent protocols as plugins

Besides the runtime protocols a client uses to talk to an agent (AG-UI,
Vercel AI, ACP, A2A), an agent speaks **agent protocols** with the world:
how it calls tools and other agents (MCP, A2A), who it is (Web Bot Auth),
what a person consented to (PAP, PACT), how it buys (UCP, ACP — the
*Agentic Commerce Protocol*, named `agentic_commerce` in code so it never
collides with the Agent Client Protocol). The map is
[poppy.md/compare](https://poppy.md/compare).

## The map

[poppy.md/compare](https://poppy.md/compare) reads an agent's visit to a
business as four questions, top to bottom: which agent is this (identity),
has the person let it act and how far (consent), how it talks and calls
tools (transport), how it buys (commerce).

| Layer | Protocol | Published by | In agent-runtimes | Libraries reused |
| --- | --- | --- | --- | --- |
| Transport | MCP, Model Context Protocol | Anthropic | client, Python ([MCP and A2A](./mcp-and-a2a#mcp)) | `mcp`, `fastmcp`, pydantic-ai |
| Transport | A2A, Agent2Agent | Google, now the Linux Foundation | server (Python) and client (both) ([MCP and A2A](./mcp-and-a2a#a2a)) | `fasta2a`, `@a2a-js/sdk` |
| Consent | PAP, Personal Agent Protocol | Sierra, Meta | both roles, through the PAP SDK ([Personal Agent Protocol](../integrations/personal-agent-protocol)) | `personal-agent-protocol`, `@datalayer/personal-agent-protocol` |
| Consent | PACT, Personal Agent Consent & Trust | Decagon, Instinct | the personal agent, both languages; a local Provider ([PACT](./pact), [PAP and PACT](./pap-and-pact)) | PyJWT, `cryptography`, `jose` |
| Identity | Web Bot Auth | IETF draft (Cloudflare and others) | signing, the key directory, verifying ([Web Bot Auth](./web-bot-auth)) | `http-sfv`, `cryptography`; Cloudflare's `web-bot-auth` |
| Identity | TAP, Trusted Agent Protocol | Visa | planned, over Web Bot Auth | — |
| Commerce | UCP, Universal Commerce Protocol | Google, with Shopify and retailers | the shopper, a test merchant ([UCP](./ucp)) | `ucp-sdk`, `@ucp-js/sdk` |
| Commerce | ACP, Agentic Commerce Protocol | OpenAI, Stripe | the buyer, a test seller ([Agentic Commerce](./agentic-commerce)) | clients generated from its JSON Schema |

## Every protocol is a Reactor plugin

In [Reactor](https://github.com/datalayer/reactor)'s terms:

- every protocol is a **Plugin**, in Python and in TypeScript, with a
  manifest and the **Contribution Points** it declares, named
  `<protocol>.<point>`: its stores, its signer, its egress;
- its defaults are **Contributions** at order 100; a host replaces one by
  contributing at a lower order (on Datalayer: IAM custody, the MCP
  gateway's egress, Vault transit signing);
- **every extension a protocol defines is a Contribution Point of its
  plugin**, `<protocol>.extension.<name>`; an implementation of the
  extension is a Contribution to it, and the protocol negotiates what it
  offers from what is contributed there;
- the **`agent-protocols` Reactor Extension** groups the plugins for
  delivery (Python entry point `datalayer.reactor.extensions`), and decides
  nothing;
- each plugin says what it is on `protocols.description`.

```python
from agent_runtimes.protocols import build_protocols_reactor, list_protocols

platform = build_protocols_reactor(plugins=[(host_manifest, host_plugin)])
for protocol in list_protocols(platform):
    print(protocol.id, protocol.version, protocol.roles, protocol.points)
```

```ts
import { buildProtocolsReactor } from '@datalayer/agent-runtimes/lib/protocols/agentProtocols';
import { listProtocols } from '@datalayer/agent-runtimes/lib/protocols/core';

const reactor = buildProtocolsReactor([hostPlugin]);
listProtocols(reactor);
```

Each protocol's points are listed in its `reactor-points.json` beside its
Python package; a table-driven test in each language holds the plugin to
it: exported under its id, declared by the plugin, its default at order 100
(or none), replaced by a lower order, gone with its plugin, two at the same
winning order failing closed.

in TypeScript) prints each plugin's description — name, id, version, layer,
roles, state — and, given an Appspec or an `app.py`, marks what the
application uses with a sentence each: the MCP servers it reaches, the PAP
companies it works with or that it is a company, the PACT Brands it is a
personal agent at, the A2A card extensions it publishes:

```text
· Agentic Commerce Protocol (agentic_commerce) 2026-04-17 — commerce, buyer, partial
● Model Context Protocol (mcp) 2026-07-28 — transport, client, server, implemented
    it reaches 1 connection(s): odoo-accounting:0.0.1
· Personal Agent Consent & Trust (pact) 1.0 — consent, personal-agent, provider, partial
· Universal Commerce Protocol (ucp) 2026-08-25 — commerce, shopper, partial
· Web Bot Auth (…) (web_bot_auth) draft-ietf-webbotauth-httpsig-protocol-00 — identity, signer, verifier, directory, implemented
```

Each description also names its entry in the agentspecs protocols catalogue
(`agentspecs/protocols`; `catalogue`: `web-bot-auth`, `acp`…), and
implements the version the catalogue says (both held by
`test_protocols_reactor_points.py` and `reactorPoints.unit.test.ts`). Studio's
Protocols page (`/agentspecs/protocols`) reads `GET /api/v1/protocols` of a
runtime of the person's against the catalogue: which protocols that runtime
speaks, in which version and roles, and which the catalogue lists that it does
not describe.

## A2A card extensions

What an agent card publishes under `capabilities.extensions` is what the A2A
plugin's extension points hold, then what the card itself declares
(`A2AAgentCard.extensions`); a URI published twice is refused. A client
negotiates with an agent from the same contributions: it activates the
extensions of the card it implements, and refuses to call an agent that
requires one it does not.

```python
from agent_runtimes.protocols.a2a import negotiate_extensions

activated = negotiate_extensions(card, platform)  # ValueError if a required one is missing
```

`examples/protocols/a2a/card_extensions.py` shows a card's extensions
published from the plugin's points, a third party's extension added by its
own plugin, and a client refusing an agent that requires one it lacks.

An application declares its own extensions in its Appspec, under `a2a`;
the runtime publishes them on the application's card after its own
(orchestration, the face), in the order written:

```yaml
a2a:
  extensions:
    - uri: https://shop.example/extensions/gift-wrap/v1
      description: Wraps an order as a gift.
      required: false
      params:
        papers: [red, gold]
```

An extension is named by an `https://` URL or a `urn:`; Datalayer's own
(`https://datalayer.ai/extensions/…`) are the runtime's and refused here.
The params are published as they are, so a name that looks like a
credential (`token`, `api_key`, `password`, …) is refused: a card is
public. See the [Appspec reference](https://agentspecs.datalayer.tech/apps/reference) (`a2a`).
