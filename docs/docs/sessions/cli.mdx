# `loop sessions`

The session's verbs, against a runtime that runs the application: `--server`
names it (`AGENT_RUNTIMES_URL`, else the local server on port 8000);
`--cloud` signs the calls with the token `datalayer login` left (or
`DATALAYER_API_KEY`), for a runtime on Datalayer. Progress goes to standard
error, the answers to standard output; every refusal is the runtime's
sentence and the command exits 1.

| Verb | What it does |
| --- | --- |
| `loop sessions list [--app <id>] [--all] [--state open\|paused\|ended] [--limit n]` | Your sessions, held and recorded, newest first; `--all` includes the archived. |
| `loop sessions show <uid>` | What a session is: state, turn, agent and harness, turns, lineage, where it runs, its harness row with the vendor's session id when the adapter exposes it. |
| `loop sessions pause <uid>` | Pause a session its runtime holds: what its conversation holds is given to its agent's memory first, when the agent has one, and its record says `paused`. |
| `loop sessions resume <uid> [--agent <id>]` | Resume a paused session — held, or from its record on a runtime of its application (`--agent` names the application's agent there). |
| `loop sessions swap <uid> --agent <spec>` | Swap the session's agent in place; the new agent is told in a sentence, printed. |
| `loop sessions clone <uid> [--at <turn>] [--agent <spec>] [--title <t>]` | A new session, paused, cut at the turn, the same or another agent. |
| `loop sessions export <uid> [-o file] [--format <id>]` | The session as a `datalayer-session/1` file. |
| `loop sessions import <file> [--agent <spec>] [--format <id>]` | A new session, paused, you its author. |
| `loop sessions end <uid>` | End it for good; its record stays. |
| `loop sessions feedback <uid>` | What people said of its answers. |

`loop apps threads` and `loop apps feedback` are retired: each answers with
the sentence naming the verb above.

A session from the terminal, in words:

```text
$ loop sessions list --app shield-mvp
e67a52b2  open    app    shield-mvp-codex        5 turns  on runtime 01m5d3e8  — The refactor
c1a9f0e3  paused  app    shield-mvp-claude-code  2 turns  not running  cloned from e67a52b2 at turn 2  — Before the refactor
$ loop sessions resume c1a9f0e3 --agent shield-mvp-claude-code
Resuming c1a9f0e3 on runtime 01m5d3e8 (shield-mvp-claude-code): 2 turns replayed.
$ loop sessions swap c1a9f0e3 --agent shield-mvp-codex
shield-mvp-codex is told: "This conversation was with Claude Code until turn 2; from here it is with Codex. What was said stays; what Claude Code kept for itself waits for a swap back."
1 allow-always answer dropped.
Swapped. shield-mvp-codex answers from turn 3.
$ loop sessions export c1a9f0e3 -o ~/before-the-refactor.session.jsonl
Exported 2 turns, 9 entries, 0 redactions → /home/ada/before-the-refactor.session.jsonl (sha256:…).
$ loop sessions import ~/before-the-refactor.session.jsonl --agent shield-mvp-claude-code
Imported as 7d2c4b10 (paused, 2 turns, 0 redactions). Resume it: loop sessions resume 7d2c4b10
$ loop sessions clone e67a52b2 --at 7
✗ Session e67a52b2 has 5 turns; there is no turn 7 to clone it at.
```

## In the REPL

Each line of a listing says what the session is a session of: `app`, an
application's, or `agent`, the session of an agent run as such (`loop -a
<agentspec>`, an agent launched from the Agent Gallery). An agent made
without an Appspec is the application of that one agent, so its
conversations are sessions of the same model: the same record, the same
states, the same verbs.

In `loop`'s prompt the conversation **is** a session, from its first
message: the prompt sends its turns to its agent's endpoint whose threads
are sessions (`/api/v1/apps/agents/<agent>/ag-ui/`).

| In the prompt | What it does |
| --- | --- |
| `/sessions [<app>]` | Your sessions, held and recorded, each with its kind and state. |
| `/pause` | Pause this session and leave. What the conversation holds is given to the agent's memory first, when its agentspec has one; the record says `paused`. On Datalayer (`loop --cloud`) the runtime is given back without asking; on your machine the server stops with the prompt. It says how to resume. |
| `/resume <uid> [<agent>]` | Go on with a session here: rebuilt from its record on this prompt's agent when the runtime no longer holds it, its conversation loaded, so your next message is its next turn. |
| `/swap <agent>`, `/clone [turn]`, `/export [file]` | Act on this session (the swap's sentence shown). |

The prompt asks its runtime what it can do first (`GET
/api/v1/runtime/status`, `agent_sessions`). A runtime that does not say it
keeps agent sessions — an older one, on a pool not updated yet — is talked to
on its plain endpoint as before, and one line says the conversation is not
listed, paused or resumed there.

Before the first message, `/pause`, `/swap`, `/clone` and `/export` say
*This conversation is not a session yet*. `/clear` starts a new session at
the next message; the one cleared stays in the record. `/browser` keeps
handing the conversation to the browser, and `/context-export` exports the
context (it was `/export` before).

```text
$ loop -a worker-marketer
> My name is Ada and I sell tea.
…
> /pause
Paused 3f6c… (worker-marketer, 1 turn): it is kept in the record.
Its memory was given 2 messages of the conversation.
Resume it: `loop -a worker-marketer`, then `/resume 3f6c…`.
$ loop -a worker-marketer
> /resume 3f6c…
Resumed 3f6c… (worker-marketer): 1 turn replayed. Your next message goes on with it; /pause, /swap, /clone and /export act on it.
> What do I sell?
```

## As `loop` starts

Started with nothing on the command line that says what to run, `loop` first
lists your **paused sessions**, before asking where a new agent should run:

```text
$ loop
? You have 12 paused sessions (8 shown; 4 more: /sessions). Go on with one, or start a new one?
❯ Start a new session
  Resume: Agent session · worker-marketer · “The autumn campaign” · on Datalayer · started 3 hours ago
  Resume: Agent session · example-simple · “My name is Ada and I sell tea.” · on this machine · started 2 days ago
  Resume: Application session · Decide · “Reply with one word.” · on this machine · started 5 days ago
  Application session · Exchange Desk · “Hi” · on Datalayer · started 6 days ago (a deployment's session: it runs in its application's name, at its address: open https://datalayer.ai/apps/exchange-desk?thread=…)
```

- The sessions kept **on this machine** are always listed; signed in to
  Datalayer (`datalayer login`, or `DATALAYER_API_KEY`), those **on
  Datalayer** too. Each says its kind, its agent or its application's name,
  its title, where it lives and when it started, newest first.
- Pick one and it is resumed **where it lives**, with its conversation
  loaded, and nobody asks where to run:
  - **an agent's session**: its agent is started, on a local server or on a
    cloud runtime;
  - **an application's session that is a Preview** — you trying an
    application, a catalogue's or one you keep in the Studio: the
    application is started as `loop apps run` starts it, from the
    catalogue's Appspec or the one the Studio keeps, and the session is
    resumed on it.
- What a terminal does not resume is drawn too, not to be picked, with why
  and where to open it (the three most recent; the rest are counted):
  - **a deployment's session** runs in its application's name, on a runtime
    the platform launches for the deployment; a terminal starts runtimes as
    you, so it is resumed at its application's address;
  - **a seat of a team run** is resumed with its run;
  - an application **written in Python** is said so when picked: its code
    reacts in its own process, and its session is gone on with on its page.
- Up to five resumable sessions are offered, then *N more: /sessions*.
- *Start a new session*, the first choice and what Enter picks, goes on to
  the usual questions.
- With no paused session nothing is printed. If Datalayer cannot be asked —
  offline, a key refused — one line says so and the start goes on.
- A run nobody is at is unchanged: `--prompt`, piped input, an agentspec
  named with `-a`, a runtime named with `--runtime`.

In the prompt, `/resume <uid>` goes on with a session of what the prompt
runs. For a session of another agent or application it says so, and that
the start's list is where it is picked: there its agent, or its
application, is started first.

## `loop plugins`

`loop plugins [<name>]` lists every reactor extension the runtime holds, its
plugins and what each contributes to the session's points, then what was
refused — a malformed contribution with the plugin's name and the reason,
an entry point that did not load with the entry point and the error. One
name given, that extension alone. See [Plugins](./plugins.mdx).
