# Harnesses

A **harness** is an agent program driven over the
[Agent Client Protocol](https://agentclientprotocol.com) (ACP): a coding agent
such as Claude Code, Codex, Gemini CLI, goose, OpenCode or OpenHands, or any
agent a framework exposes over ACP (fast-agent, LangChain's Deep Agents,
LlamaIndex's `workflows-acp`, …). Agent Runtimes drives one as it drives its
own agents: it launches the program in the runtime, speaks ACP to it over
stdio, lends it tools through the MCP gateway, writes the application's skills
into its workspace in its own format, and serves it over every protocol the
runtime serves — A2A, AG-UI, the session API, the embed. The harness has no
face of its own and reaches nothing the runtime did not lend.

This page says what is built today and what is not. The plan is `SHIELD.md`
in the landing's `plans/`; the boxes named below are its.

## The spec (built: agentspecs 0.0.100, SH-01)

A harness is a spec kind of agentspecs, one YAML per harness under
`agentspecs/harnesses/`. An agent spec names one with `harness:` where it says
`pydantic-ai` or `vercel-ai` today:

```yaml
# agentspecs/harnesses/claude-code.yaml
id: claude-code
version: 0.0.1
name: Claude Code
description: Anthropic's coding agent, driven over ACP through the Agent Client Protocol project's adapter.
docs: https://github.com/agentclientprotocol/claude-agent-acp
acp:
  command: npx
  args: ["-y", "@agentclientprotocol/claude-agent-acp@0.91.0"]   # pinned
  protocol_version: 1
  load_session: true            # read from initialize, refused if it lies
  mcp: lend                     # lend | own | none
  modes: [default, plan, acceptEdits, bypassPermissions]
requires:
  secrets: [ANTHROPIC_API_KEY]  # ids of env-vars/, declared as skills declare theirs
  binaries: [node, git]
terms:
  served_to_third_parties: api_key_only   # subscription credentials refused
  licence: Apache-2.0 (adapter); Anthropic Commercial Terms of Service (the agent)
skills:
  format: skill-md              # SKILL.md folders, the agentskills.io specification
  dir: .claude/skills
honours:
  model: true                   # takes the agent's `model:`
  subagents: false              # has its own: `subagents:` is refused
instructions_file: CLAUDE.md
```

```yaml
# an agent on it
id: coder
name: Coder
harness: claude-code
model: bedrock:us.anthropic.claude-sonnet-4-6
```

`acp` says how it is launched and driven; `requires` what it needs in the pod
(secrets as ids of the env-vars catalogue, executables on the path, one the
image installs for it pinned as `name@version`); `honours` and `skills` what of
an agent spec it can take; `instructions_file` where the application's
instructions are written for it (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`,
`.goosehints`); `terms` the terms it is served under. Nothing in the fields is
specific to coding: a framework's agent over ACP is described the same way.

The catalogue: `claude-code`, `codex`, `gemini-cli`, `goose`, `opencode`,
`openhands`, one framework over ACP, `fast-agent`, and **`custom`** — the one
harness with no `acp` block, whose command an organization's own harness spec
names; the shared catalogue refuses it to any agent. The reference page of
every harness, generated from the specs, is
[agentspecs.datalayer.tech/harnesses](https://agentspecs.datalayer.tech/harnesses).

`make specs` generates the Python and TypeScript catalogues as for every kind:
`agent_runtimes/specs/harnesses.py` (`HARNESS_CATALOGUE`, `get_harness`,
`list_harnesses`) and `src/specs/harnesses.ts` (`getHarness`,
`listHarnesses`), typed by `HarnessSpec` in `agent_runtimes.types` and
`src/types/agentspecs.ts`.

### Refused at load

A spec that asks what its harness cannot do is refused at load, in a sentence,
wherever `harness:` is read — the generated catalogue (`generate_agents.py`
refuses it at generation), `Agentspec` (a `ValidationError` as the spec is
built), the Studio's instant checks (`checkAppspec`) and the variant vocabulary
(`src/runtimes/variants.ts`):

- `There is no harness named 'x': one of pydantic-ai, vercel-ai, claude-code, …`
- `The harness 'custom' names no command: an organization's own harness spec names it, and is never typed into a form.`
- `The harness 'claude-code' has its own subagents: drop `subagents:`.`
- `The harness 'x' does not take a model: drop `model:`.` and `The harness 'x' reads no skills: drop `skills:`.` — for a harness whose `honours.model` is false or whose `skills.format` is `none`; none of the catalogue's seven is, an organization's own may be.

`harness_problems(harness_id, model=, subagents=, skills=)` in
`agent_runtimes.types` says them; `unservedHarnessProblem(spec)` in
`src/runtimes/variants.ts` is the TypeScript side.

## The register (built: SH-04's part in agentspecs)

`agentspecs/harnesses/register.yaml` is the register of SHIELD §3.3: every
harness of the catalogue with its adapter, the version pinned, its licence,
the agent's terms, the credential it takes, whether serving it to third
parties is permitted, its tier restrictions and the binaries it needs — each
with where it was read, on 15 October 2026. A harness without an entry, or
whose spec disagrees with its entry, does not load; a harness whose terms are
unknown is not in the catalogue. The entries, in short:

## The adapter (built: SH-10's adapter, SH-11, SH-12's runtime side, SH-13, SH-18, SH-19's `loop`; 15 October 2026)

`agent_runtimes/adapters/acp_agent.py` is `ACPAgent(BaseAgent)`, the harness
as a Datalayer agent, on the `agent-shield` package's engine
(`datalayer-agent-shield` 0.1.1, `agent_shield.acp`, `policy`, `register`):
the class **is** the package's `ShieldProxy` with the runtime as its outer face,
so the proxy's own interception — tool calls classed and decided, `fs/*` and
`terminal/*` answered against the workspace, the limits counted,
`allow_always` a session rule — runs unchanged, and agent-runtimes adds only
what needs the runtime.

- **Launch and negotiate.** `initialize` resolves the harness's command from
  its spec — an `npx` adapter is taken from `~/.agent-shield/harnesses/<id>@<version>`
  (`agent-shield setup --harness <id>`) or from the PATH (the image's install,
  SH-05), **never fetched at first run** — gives the process its spec's plain
  variables and its declared secrets by name (a missing one is refused in a
  sentence), launches it over stdio in the workspace (`AGENT_RUNTIMES_WORKSPACE_ROOT`,
  refused when unset), runs `initialize` (protocol version 1, `fs` and
  `terminal` on) and refuses what the spec asked that the agent did not
  advertise (`loadSession`).
- **The events** (§4.1's table): `agent_message_chunk` → `text`;
  `agent_thought_chunk` → `thought`; `tool_call` → `tool_call` with `kind`,
  `status`, `arguments`, `awaiting: approval` while pending, the policy's
  sentence; `tool_call_update` → `tool_call` (in progress, with its displays)
  or `tool_result` (completed or failed, the `diff` and `terminal` displays in
  `display`); `plan` → `plan`; `available_commands_update` → `commands`;
  `current_mode_update` → `mode`; the turn's end → `done` with the stop
  reason. A malformed update, or an action a policy leaves to the person, ends
  the turn with a sentence (`[Shield] …` as text, `done` with `stop_reason:
  refusal` and the sentence).
- **Permissions are Rules** (§4.5, SH-12). ACP's `kind` is classed by the
  package's one table (`agent_shield.policy.class_of`: `other` → write, fail
  closed; the table-driven test both ways is `test_acp_agent.py`). The policies
  in force are the application's Rules on classes read into a `team`-scope
  document (`agent_runtimes/guardrails/shield_policy.py`; `if_asked` read as
  *ask me first*) above decision 5's default. *Do it* answers `allow_once`
  without asking; *ask me first* raises the approval through the runtime's
  tool approvals (Waiting for you, ai-agents `/ws`, `GET /tool-approvals/{id}`)
  with the caller's token and answers what the person chose — a note saying
  "always" picks `allow_always`, a session rule gone with the session; *leave
  it to me* answers `reject_once` with the sentence; a turn cancelled while it
  waits answers `cancelled`. A Rule of the application is never loosened by a
  session rule (§6.3).
- **Files and terminals** (§4.6, SH-13): `fs/read_text_file`,
  `fs/write_text_file` and `terminal/*` are answered by the runtime against
  the workspace, each a tool row (`Read README.md — do it`, kind `read`;
  `Write hello.txt — do it`, kind `edit`, the diff as its display; `Run …`,
  kind `execute`, the terminal as its display, its output and exit kept) and a
  decision; a path outside the workspace is refused in a sentence before any
  rule.
- **The record** (§4.8, SH-18): the Shield's audit rows are the
  application's record — a `decision` for what a policy decided, a `tool_call`
  for what was done (the diff as its hash and size), an `approval` for what
  the person answered, the `turn` and the run's end — kept as
  `record.include` names them. The harness's session is kept in the protocol
  state store; a restarted runtime loads it when the harness advertises
  `loadSession` and says in a sentence when the replay and the record differ;
  otherwise it **says** it starts over, never pretends to continue. Deleting
  the agent (a paused deployment stops its runtime) ends the process.
- **Served over** `ag-ui` (`transports/agui_stream.py`: `BaseAgent.stream` as
  AG-UI events — the thinking events, `TOOL_CALL_*`, `TOOL_CALL_RESULT` with
  the displays, `datalayer.harness.<plan|commands|mode|tool_call>` custom
  events), `acp` and `a2a`; `vercel-ai` is refused in a sentence (it reads a
  pydantic-ai agent, SH-16).
- **`loop --harness <id>`** runs a harness on this machine over stdio, the
  directory `loop` runs from as its workspace, decision 5's policy, the record
  in the terminal; a missing adapter, secret or workspace is refused before
  anything starts. **`loop harnesses`** lists the catalogue with each one's
  adapter, credential, third-party serving and licence.
- **The orchestrator's channel** (SH-02's agent-runtimes part):
  `orchestration/adapters/acp.py` takes the package's channels as its
  `ShieldChannel` — `stdio:<command line>` launches a local agent, `ws://`
  connects — and no longer says *no stdio yet*; the client it was first built
  on (`transports/clients/acp_client.py`) is out from under it.

Tests: `test_acp_agent.py` (45: every update kind, the permissions, the
kinds table both ways, sessions and the record, the resolution of a catalogue
harness, Claude Code live as a marked test) and `test_acp_agent_transports.py`
(9: AG-UI, the orchestrator's channel, the runtime started with a harness),
all on the ACP SDK's fake agent (`tests/fixtures/acp_fake_agent.py`,
agent-shield's): the only Anthropic key at hand has no credit, so Claude
Code's first live turn through the adapter waits on a funded key.

  beyond decision 5's, the audit's export, the report (SH-30 to SH-39, SH-50
