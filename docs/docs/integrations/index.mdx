# Integrations

Agent Runtimes provides a flexible agent architecture built on top of [Pydantic AI](https://ai.pydantic.dev).

For the full Agentspecs reference and platform documentation, see [datalayer.ai/docs](https://datalayer.ai/docs).

Agent Runtimes also provides a model-safe integration with
[Personal Agent Protocol](./personal-agent-protocol): Python and TypeScript
consume the same PAP SDK profile and expose verified public summaries while
authorization and Session secrets stay in host services.

## Why Pydantic AI?

We chose Pydantic AI as our foundation because it provides:

- **Type Safety** — Full type checking with Pydantic models for inputs and outputs
- **Structured Outputs** — Reliable JSON responses from LLMs with validation
- **Tool Calling** — First-class support for function tools and MCP toolsets
- **Multi-Model Support** — Works with Anthropic, OpenAI, Google, Azure, and more
- **Production Ready** — Well-tested and actively maintained

## Creating an Agent

```python
from pydantic_ai import Agent
from agent_runtimes.mcp import (
    get_config_mcp_toolsets,
    initialize_config_mcp_toolsets,
)

# Start the MCP servers of mcp.json (the agent-runtimes server does this at startup)
await initialize_config_mcp_toolsets()
# The toolsets that started, ready for Pydantic AI
mcp_toolsets = get_config_mcp_toolsets()

# Create an agent with MCP tools
agent = Agent(
    "anthropic:claude-sonnet-4-20250514",
    instructions="You are a helpful assistant with access to web search.",
    toolsets=mcp_toolsets,
)
```

## UI Integration Examples

### Notebook and document AI assistants

The `NotebookAgentsRuntime` and `DocumentAgentRuntime` components this page used to show are gone. A notebook or a document beside a chat is now a page the agent-runtimes server serves for one agent:

```text
http://localhost:8765/static/agent-notebook.html?agentId=<agent-id>
http://localhost:8765/static/agent-document.html?agentId=<agent-id>
```

The notebook page also takes `jupyterBaseUrl` and `jupyterToken`. In your own React application, put the [Chat](../chat) component beside your editor and register the editor's tools with `useFrontendTool` (see [Hooks](../hooks)).

### Custom Agent Deployment

There is no `AgentRuntimesApp` class. The server is the FastAPI application `create_app()` returns (what `agent-runtimes serve` runs); an agent built in Python is wrapped for Agent Runtimes and registered with a transport:

```python
import uvicorn
from pydantic_ai import Agent

from agent_runtimes import create_app
from agent_runtimes.adapters import PydanticAIAdapter
from agent_runtimes.routes.agui import register_agui_agent
from agent_runtimes.transports import AGUITransport

agent = Agent(
    model='anthropic:claude-sonnet-4-5',
    instructions='You are a helpful assistant.',
)

app = create_app()
adapter = PydanticAIAdapter(agent, name='my-agent', agent_id='my-agent')
register_agui_agent('my-agent', AGUITransport(adapter, agent_id='my-agent'))
uvicorn.run(app, port=8765)
```

An agent described by an [agentspec](../agentspecs) needs no code: `agent-runtimes serve --agent-id <spec-id>` creates it and registers it with every transport.

## Runtime Lifecycle Management

Use runtime hooks to launch or attach compute resources and auto-create agents:

```typescript
import { useAgentRuntimes } from '@datalayer/agent-runtimes/lib/hooks';

const { isReady, endpoint, status, launchRuntime } = useAgentRuntimes({
    autoCreateAgent: true,
    agentConfig: {
        model: 'anthropic:claude-sonnet-4-5',
        systemPrompt: 'You are a helpful AI assistant.',
    },
});

await launchRuntime({
    environmentName: 'python-simple',
    creditsLimit: 100,
    type: 'notebook',
});
```

## Hooks Integration (Pydantic AI)

Agent Runtimes reuses Pydantic AI capability hook methods directly for tool approval and guardrail flows.

Common hook points:

- `before_tool_execute`
- `after_tool_execute`
- `on_tool_execute_error`
- `deferred_tool_calls`

### Agentspec Hook Example

```yaml
tool_hooks:
    actor: "${USER}"
    audit_log_path: "/tmp/agent_runtimes_tool_approvals_audit.jsonl"
    before_tool_execute:
        - function: agent_runtimes.integrations.tool_policy:evaluate_tool_request
    after_tool_execute:
        - python: |
                print("success", payload.get("tool"), payload.get("status"))
    on_tool_execute_error:
        - python: |
                print("error", payload.get("tool"), payload.get("error_type"))
```

For the plugin mechanisms these hooks belong to, see [Plugins](/plugins)
and [Hooks](/hooks).

## Model Providers

Agents can use models from multiple providers:

| Provider | Model Format |
|----------|-------------|
| Anthropic | `anthropic:claude-sonnet-4-20250514` |
| OpenAI | `openai:gpt-4o` |
| Azure OpenAI | `azure:gpt-4o` |
| AWS Bedrock | `bedrock:us.anthropic.claude-3-sonnet` |
| Google | `google:gemini-1.5-pro` |

## Per-Request Model Selection

Switch models dynamically without restarting:

```python
# Use Claude for complex reasoning
result = await agent.run("Analyze this data...", model="anthropic:claude-sonnet-4-20250514")

# Use GPT-4 for creative tasks
result = await agent.run("Write a poem...", model="openai:gpt-4o")
```
