# Agent Substrate

[Agent Substrate](https://ate.dev) ("ate") runs containers as sandboxed,
stateful **actors** on Kubernetes. Each actor runs in a gVisor or microVM
sandbox. Many actors share a small pool of warm worker pods. An idle actor is
suspended to a snapshot of its memory and files and resumed on its next
request.

Agent Runtimes runs as an actor with `agent-runtimes serve --target ate`. Every
agentspec of the library can then run as an actor that suspends while it waits
and resumes where it stopped.

This page is written for Agent Substrate **1.0.0**. To run Agent Runtimes
through [kagent](./kagent), which itself runs on Agent Substrate, see that page.

## What the target does

| | |
|---|---|
| Listens on | `0.0.0.0:80`, the actor's default port (`ATE_PORT` to change it) |
| Wakeup probe | `GET /ate/wakeup`, answered 200 once the server serves |
| Identity | `GET /ate/identity`: atespace, actor, actor uid, runtime uid, wakes |
| Agent at start | the agentspec of `AGENT_SPEC_ID` as `default`; none when unset (agents are created through the API) |

### Identity is read at each wake

Every actor of a template starts from the template's **golden snapshot**, the
memory of its first actor. Anything the process read at start (environment,
files, a token) is the golden actor's, the same in every actor. So the target
reads the actor's identity from its `systemInfo` volume (`/run/ate/actor-name`,
`atespace`, `actor-uid`) **on each wake**. A wake is the first call to the
wakeup probe after a quiet spell: Agent Substrate calls the probe on every
resume, and never while the actor runs.

On each wake:

- the identity is read again. When the actor is named `rt-<uid>`, the
  Datalayer runtime it serves, `DATALAYER_RUNTIME_ID` is set to that uid;
- when the template projects a trust bundle at `/run/substrate/certs/ca.pem`
  and no other CA file is configured, `SSL_CERT_FILE` and `REQUESTS_CA_BUNDLE`
  name it.

### No credential in the actor

A template's environment is literal, the same for every actor, and part of
every snapshot. Model and tool keys are put in the actor's outbound requests by
Agent Substrate's **egress gateway**, from the actor's `EgressPolicy`. The actor
sends a placeholder. `agent-runtimes-ate template` refuses an environment
variable whose name says key, token, secret, password or credential.

## Run an agentspec as an actor

You need a cluster with Agent Substrate installed (its
[quickstart](https://ate.dev/docs/get-started/quickstart/)), `kubectl ate`, a
`WorkerPool`, and an atespace.

1. Build and push the actor image, `docker/Dockerfile.ate`, and note its
   **digest**. Templates take images by digest only.

   ```bash
   docker build -f docker/Dockerfile.ate \
     --build-arg AGENT_RUNTIMES_VERSION=1.6.36 \
     -t registry.example.com/agent-runtimes-ate:1.6.36 .
   docker push registry.example.com/agent-runtimes-ate:1.6.36
   ```

   It installs Agent Runtimes from PyPI (1.6.36 or later) with the `a2a`, `ui`,
   `openai`, `anthropic` and `aws` extras, and nothing else: no Node.js, no
   Chromium. Agent Substrate snapshots an actor's memory and filesystem on
   suspend and restores them on resume, so a lean image resumes faster;
   `docker/Dockerfile.agent-runtime` works too, several times slower to restore.

2. Render the template and create it:

   ```bash
   agent-runtimes-ate template \
     --atespace agents --name crawler \
     --image registry.example.com/agent-runtimes@sha256:<digest> \
     --agent-spec-id crawler \
     --worker-label workload=agent-runtimes \
     --env AGENT_RUNTIMES_MODEL=openai:gpt-5-mini \
     --env OPENAI_BASE_URL=https://inference.example.com/v1 \
     | kubectl ate create actor-template -f -
   ```

   The template runs `agent-runtimes serve --target ate`, probes `/ate/wakeup`,
   mounts the actor's metadata at `/run/ate`, the trust bundle at
   `/run/substrate/certs`, and a durable `/data`, and sizes each actor
   (`--cpu-millicores`, 2000 by default; `--memory-bytes`, 2 GiB). The first
   wake may take up to `--wakeup-timeout-seconds` (180 by default: Agent
   Substrate's own 30 s was too short for a golden actor on burstable cloud
   nodes under gVisor). `-o yaml` prints YAML.

3. Create an actor and give it its egress:

   ```bash
   kubectl ate create actor crawler-1 -a agents --template crawler

   agent-runtimes-ate egress-policy \
     --host inference.example.com \
     --credential ate-secret://k8s.io/default/agents/inference/key \
     | kubectl ate create egress-policy crawler-1 -a agents -f -
   ```

   The gateway replaces the `Authorization` header of requests to that host
   with `Bearer <the Secret's value>`. Set the model client's key to any
   placeholder.

4. Talk to it:

   ```bash
   kubectl ate proxy actor crawler-1 8000:80 -a agents
   curl http://localhost:8000/ate/identity
   ```

   Any Agent Runtimes protocol (AG-UI, Vercel AI, A2A, MCP) works through the
   proxy. The first request resumes a suspended actor.
   `kubectl ate suspend actor crawler-1 -a agents` suspends it again.

## Command reference

```bash
agent-runtimes-ate template --help
agent-runtimes-ate egress-policy --help
```

| Variable | Default | Meaning |
|---|---|---|
| `AGENT_RUNTIMES_TARGET` | `ate` (set by the template) | the target |
| `AGENT_SPEC_ID` | unset | the agentspec served as `default` |
| `ATE_PORT` | `80` | the port |
| `ATE_SYSTEM_INFO_DIR` | `/run/ate` | where the actor metadata is projected |
| `ATE_TRUST_BUNDLE` | `/run/substrate/certs/ca.pem` | the trust bundle |

## Limits

- Connections to the outside do not survive a suspend. Clients reconnect on
  their next call, and tokens fetched before a suspend may have expired.
- Only HTTP reaches the actor (port 80, or other ports through
  `kubectl ate proxy`). Raw TCP on other ports does not.
- Agent Substrate needs Kubernetes with `ClusterTrustBundle`,
  `ClusterTrustBundleProjection` and `PodCertificateRequest` enabled. See its
  documentation for the supported versions.
